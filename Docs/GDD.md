## 1. 개요

### 1.1 한 줄 소개

멸망 직전의 마지막 영지에서, 낮에는 자원을 모으고 마을을 경영하며 밤에는 몰려오는 몬스터로부터 본진을 지키는 그리드 기반 타워 디펜스 게임.

### 1.2 장르

타워 디펜스 + 시티빌더(경영 시뮬레이션) 하이브리드, 로그라이크 요소 결합

### 1.3 세계관 / 테마

- **테마**: 중세 판타지
- **배경**: 대륙은 무너졌다. 왕국의 깃발도, 기사단의 맹세도 밤의 대군 앞에 모두 재가 되었다. 마지막 뿌리를 내린 생존자들이 찬란한 태양 아래 희망을 꿈꾼다.
- **낮**: 해가 떠 있는 동안이 기회다. 자원을 모으고, 타워를 세우고, 병력을 준비한다.
- **밤**: 어둠과 함께 몬스터가 몰려온다. 새벽이 올 때까지 버텨야 한다.
- 배경은 저주받은 땅 위에 남은 중세 성곽 마을. 몬스터 테마는 논의 중이며 변경 가능.

### 1.4 비주얼 컨셉

- **오쏘그래픽 카메라 + "움직이는 미니어처(디오라마)" 룩** — 2.5D보다 미니어처 착시 우선.
- 구현 수단: 틸트-시프트 블러(스크린 Y 밴드) + 컬러 그레이딩(채도·따뜻한 톤) + 강한 키 라이트 + 툰 셰이더(소프트 램프).
  상세 설계·확정 결정은 `Docs/Rendering/VisualLookPipeline.md`(#148) 참조.
- 세부 튜닝 수치(채도·블러 밴드·라이트)는 TBD — 구현 중 스크린샷 비교로 확정.

3개 레퍼런스에서 부분적 요소를 가져와 통합.

### 종합 재미 요소

- **경영이 곧 전투력**: 경영 공간에서 확보한 자원으로 전투 공간에 타워를 배치하고 방어선을 구축
- **실시간 전투 참여**: 전투는 자동 진행되지만 플레이어 스킬로 직접 개입 가능
- **로그라이크 요소**: 매 판 새로운 유물/선택지로 타워를 조합해 나만의 빌드 완성

## 3. 핵심 시스템

### 3.1 두 개의 공간 (분리된 이중 확장 구조)

- **경영 공간**: 자원 생산, 주민 배치, 건물 건설, 영토 확장
- **전투 공간**: 타워 배치로 본진 수비 (병사 배치는 도입 여부 미확정 — §5.4 참고)
- 두 공간의 영토는 각각 독립적으로 관리되며 동시에 확장 가능

### 3.2 자원 흐름 (RESOURCE FLOW)

자원은 **기본 자원 3종(나무 · 철 · 식량)** + **미개척 영지 자원(가변 종류)** + **마나석(상위)** 으로 구성된다.

- **기본 자원(나무/철/식량)**: 각각 **나무꾼의 집 · 광산 · 농장**에 주민을 배치해 생산한다. 건물 건설, 건물 업그레이드, 타워 강화에 사용(병사 시스템 도입 시 병사 훈련에도). 획득 경로는 **(1) 생산 건물에 주민 배치, (2) 영토 확장 보상** 둘 다 가능. 식량도 이 3종 중 하나인 순수 기본 자원이다(종전 '식량 종속' 모델은 폐기, 아래 계약 참고).
- **미개척 영지 자원(가변 종류)**: 경영 영토 확장(§5.3)으로 새 **미개척 영지**를 확보하면 그 영지 고유의 **새 자원 종류 + 생산 라인**이 해금된다. 새 라인은 **주민을 배치하지 않고, 매일 자원 정산 시 일정량이 꾸준히 자동 수급된다**(주민·식량과 무관한 패시브 수입. 영지별 일일 수급량은 TBD). 확보한 영지 수가 늘수록 자원 종류와 총 일일 수급이 함께 늘어난다.
- **마나석**: 영토 확장·전투 보상으로만 얻는 상위 자원 → 스킬 건물 업그레이드, **연금술사의 집 교환**(#211) 등에 사용.
- **연금술사의 집 = 교환소(#211)**: 마나석을 다른 자원으로 바꾸는 **단방향 교환소**. 낮에만 이용 가능하고, 교환 대상은 마나석을 제외한 **7종**(기본 3종 + 미개척 영지 자원 4종)이다. **역교환(자원 → 마나석)은 없다.** 교환비는 `BuildingAsset.Exchange.Offers`(SO)에 authoring하며 밸런싱 수치는 TBD — 미개척 영지 자원은 영토 확장 동기를 해치지 않도록 확실히 비싸게 잡는다.
  - **업그레이드 시 교환 효율이 개선된다**(§5.7): 지불하는 마나석은 그대로인데 **받는 자원량이 늘어난다** (예: 마나석 10 → 나무 10 이던 것이 업그레이드 후 마나석 10 → 나무 15). 레벨당 배율은 `Exchange.UpgradeLevels[].GainMultiplier`에 authoring한다. **설계는 확정, 구현은 아직**(#211 범위 밖 — 선행 작업은 §5.7 참고).
  - 상세는 `Docs/ManagementArea/Resources.md`.

> **자원 흐름 계약(이번 방향 전환)**: 미개척 영지 자원은 주민 생산이 아니라 **영지 해금 시 열리는 매일 자동 수급 경로**로 얻는다(영토 확장 보상의 일종). 계약 #3의 "기본 자원 = 주민 생산·영토 보상"은 유지되고, 확장 자원은 영토 해금이라는 정당한 원천에서 나오므로 계약 위반이 아니다. **직전 설계였던 '식량 소모 → 확장 자원 변환'(식량 종속 중앙 조절점)은 폐기**되어 식량은 다시 순수 기본 자원 하나로 돌아간다. **마나석 → 자원 교환 경로는 연금술사의 집(교환소)으로 확정**(#211, 위 항목 · WL-042 해소). 교환은 마나석을 **쓰는** 경로일 뿐 새 획득 경로가 아니다 — 지갑에 자원을 넣는 창구는 `ManagementController.TryExchange` 하나뿐이고 마나석 차감과 지급이 한 트랜잭션이라, 마나석 없이 자원이 생기는 길은 없다. **본진 업그레이드 비용도 종결(#229)**: 자원 종류를 자유롭게 authoring하며(현재 나무·철·마나석) 차감은 다른 업그레이드와 같은 `TrySpend` 게이트웨이를 거친다 — 지갑에 자원을 **넣지 않는 순수 소비 경로**라 계약 위반이 아니다(WL-042 완전 해소).

### 3.3 성장 루프 (GROWTH LOOP)

```
(최초 1회) 초기 자원 지급
  ↓
[낮] 타워 배치 + 주민 배치 → 낮 종료
  ↓
[밤] 전투 영토 확장 → 몬스터 스폰·이동 → 타워 공격 + 플레이어 스킬 개입
  ↓
웨이브 클리어 → 자원 정산 + 마나석 지급
  ↓
[낮] 경영 영토 확장(강제 1회, 새 미개척 영지 = 새 자원 라인 해금)
     → 주민 배치 + 건물 업그레이드
     (생산 건물: 주민당 획득 자원량 증가 / 마법연구소: 스킬 강화 / 본진: 하위 건물 Max 해금 + 교환 효율 — 전부 구현 완료)
     → 낮 종료
  ↓
(정해진 웨이브 수만큼 반복)
  ├─ 최종 웨이브 클리어 → 게임 승리
  └─ 웨이브 실패 (본진 HP = 0) → 즉시 게임 오버
```

※ 병사 시스템 도입 시 밤 페이즈에 병사 배치 단계가 추가됨 (도입 여부 미확정 — §5.4 참고)

### 3.4 승패 조건

- **게임 오버**: 전투 중 본진 HP가 0이 되면 해당 Run 종료
- **클리어 조건**: 모든 스테이지를 클리어하고 최종 보스를 처치하면 승리

## 4. 게임 루프 — 하루 2단계 사이클

```
낮(경영) → 밤(수비) → (다음날로 반복)
```

### 4.1 낮 (Morning Phase)

목표: 자원을 생산하고 건물·타워를 준비한다.

| 행동           | 공간 | 내용                                                                                                                      |
| -------------- | ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 본진 체력 회복 | 경영 | 낮 시작 시 자동 회복                                                                                                      |
| 주민 배치      | 경영 | 보유한 주민 수만큼 생산 건물 또는 훈련장에 배치 (배치는 매일 초기화)                                                      |
| 주민 수 증가   | 경영 | 본진을 클릭해 자원을 소모하고 **선택 상한**을 1명씩 늘린다 — 시작 2명 / 최대 10명, 누진 비용(§5.1). 마을 군중 수는 고정이라 늘지 않는다. 늘어난 상한은 다음날에도 유지 |
| 건물 건설      | 경영 | 새 건물을 지어 할 수 있는 작업(생산·업그레이드 등)을 해금하는 시스템. 해금 대상 목록은 미정                               |
| 건물 업그레이드 | 경영 | 생산 건물(나무꾼의 집/광산/농장) 업그레이드 → 주민당 획득 자원량 증가 (§5.7). 마법연구소 = 마나석으로 레벨 업(효과=스킬 기본 스탯 배율 강화 #205 + 착탄 이펙트 교체 #206, 구현 완료). **본진 업그레이드 → 하위 건물 Max 레벨 해금 + 연금술사 교환 시 받는 자원량 증가(#229 구현 완료)** — 연금술사는 자체 업그레이드 버튼 없이 본진 레벨을 따른다 |
| 경영 영토 확장 | 경영 | 웨이브 클리어 후 인접 **미개척 영지** 하나를 선택해 확장, 영지마다 고유 **새 자원 생산 라인 해금**(§5.3) (현재는 강제 1회, 이후 자원 소모형 전환 검토)      |
| 타워 배치      | 전투 | 확보한 자원으로 그리드에 타워 배치                                                                                        |

### 4.2 밤 (Evening Phase)

목표: 배치한 타워와 플레이어 스킬로 몬스터의 침공을 막아낸다.

| 행동           | 공간 | 내용                                                                       |
| -------------- | ---- | -------------------------------------------------------------------------- |
| 전투 영토 확장 | 전투 | 밤 시작 시 영토 1칸 자동 확장                                              |
| 몬스터 침공    | 전투 | 정해진 경로(웨이포인트)를 따라 본진으로 진격                               |
| 타워 공격      | 전투 | 사거리 내 몬스터를 자동 공격                                               |
| 플레이어 스킬  | 전투 | 범위를 지정해 발동, 몬스터에게 피해를 준다 (밤 동안 유일한 능동 개입 수단) |

### 4.3 밤 종료 — 결과 분기

- **웨이브 클리어**: 주민 배치로 얻은 자원 정산 + 마나석 지급 → 낮으로 전환
- **최종 웨이브(보스) 클리어**: 게임 승리
- **웨이브 실패** (본진 HP = 0): 즉시 게임오버

## 5. 세부 시스템

### 5.1 주민 시스템

> **주민에는 두 개의 수가 있다 — 혼동하지 말 것.**
>
> | | 무엇 | 값 | 무엇을 정하는가 |
> |---|---|---|---|
> | **군중** | 마을에 살며 돌아다니는 주민 | **고정 풀** (기준 20~30) | 화면에 보이는 사람 수 |
> | **배치 상한** | 한 번에 **선택·배치**할 수 있는 수 | 시작 2 / 최대 10 (`MaxVillagers`) | 생산에 투입 가능한 인원 |
>
> **군중은 고정이고, 성장하는 것은 선택 상한이다.** 본진을 올려도 마을 인구가 늘지 않고, **한 번에 부릴 수 있는 사람 수**가 는다. 화면의 주민 수는 `군중 − 배치된 수`이며, 배치된 주민은 건물 안에 있으므로 화면에서 사라진다.
>
> 왜 이렇게 나누는가 — 군중을 `MaxVillagers`(최대 10)에 맞추면 **마을이 밋밋하고**, 넓게 퍼진 주민을 일일이 찾아 드래그해야 해서 불편하다. 그래서 군중은 넉넉히 두고 **한 번에 조작할 수 있는 수에만 상한을 건다.** RTS가 선택 상한을 두는 것과 같은 이유다.
>
> 상세 명세는 `Docs/ManagementArea/Resident.md` §3.1(인원 계산)·§8(선택·드래그).

**선택 상한 (`MaxVillagers`) — 아래가 전부 이 수에 대한 것이다**

- **시작 2명**, 최대 10명
- **주민 수 증가 — 본진에서 자원을 소모해 1명씩 늘린다** (#227 구현 완료)
  - 낮에만 가능. 자원이 부족하면 실패하고 아무것도 차감되지 않는다(원자적)
  - 비용은 **누진**이며 회차가 오를수록 요구 자원 **종류**도 늘어난다(예: 나무 60 → 나무 60 + 철 20)
  - 후반 회차는 **미개척 영지 자원**(금·루비·다이아)을 요구한다 → 주민을 계속 늘리려면 영토 확장이 사실상 필수다(§5.3과 연결)
  - **상한은 별도 수치가 아니라 비용 테이블의 행 수로 표현한다**(시작 2명 + 8행 = 10명). 상한과 비용이 한 곳에 있어 어긋날 수 없다. 8행을 모두 쓰면 버튼이 MAX로 바뀐다
  - 수치는 placeholder — 밸런싱은 추후 조정
- 늘어난 주민 수는 **다음날에도 유지**된다. 하루가 끝나면 **배치만** 초기화된다
- 배치처: 기본 자원 생산 건물(나무/철/식량), or 훈련장(병사 생성, 병사 시스템 도입 시). **미개척 영지 자원 라인은 주민 배치처가 아니다** — 매일 정산 시 일정량이 자동 수급되므로(§3.2).
- ⚠️ **영토 확장으로 선택 상한이 늘어나는 경로는 현재 구현이 없다** — 종전 설계의 `GainResidentEffect`가 #166에서 영토 효과 SO 계층과 함께 삭제됐다(§5.3). 되살릴지, 본진 증가 하나로 통합할지는 TBD.

**군중 (앰비언트) — #276 구현 완료**

- 마을에 사람이 산다는 것을 보여주는 **연출 개체군**이다. 자원을 생산하지 않고 일터로 가지 않는다
- **고정 풀**이라 본진 업그레이드로 늘지 않는다. 기준 20~30이며 정확한 값은 성능 실측 후 확정
- 낮에만 존재한다 — 밤이 되면 가장 가까운 문으로 뛰어 들어가고 아침에 다시 나온다
- 길을 걷고, 마주치면 인사하고 수다 떨고, 혼자 있으면 춤춘다. 전부 확률로 갈리며 개체마다 사교성이 다르다
- ⚠️ **군중은 자원 로직을 소유하지 않는다.** 배치 수의 단일 진실 원천은 끝까지 `ManagementController`이고, 군중은 그 숫자를 **화면의 사람 수로 번역해 보여줄 뿐**이다

### 5.2 건물 건설 & 타워 배치

- 경영 공간: 새 건물을 지어 할 수 있는 작업(생산·업그레이드 등)을 해금 — 해금 대상 목록은 미정
- 전투 공간: 확보한 자원으로 타워 건설
- 낮 동안 경영 공간은 건물을, 전투 공간은 타워를 배치하는 구조로 명확히 분리

**되돌리기(Undo)** — 낮 동안 한 **타워 배치·타워 합성**은 되돌릴 수 있다.

- 화면에 상시 표시되는 되돌리기 버튼으로 **가장 최근 조작부터 하나씩**(LIFO) 되돌린다. 지불한 자원은 100% 돌아온다.
- 밤으로 넘어가면 그날의 조작이 **일괄 확정**되어 더는 되돌릴 수 없다. 밤에는 버튼이 비활성이다.
- 깊이 상한 20. 다시 실행(Redo)은 없다.
- **경영 공간 조작(건물 건설·주민 배치·업그레이드)은 대상이 아니다.**
- ⚠️ 되돌릴 수 있는 것은 "방금 한 조작"뿐이다 — **어제 놓은 타워를 없애는 임의 철거 경로는 여전히 없다**(TBD).

### 전투 타일 지형 효과

전투 공간의 일부 건설 가능 타일에는 타워 능력치를 증가시키는
지형 효과가 부여될 수 있다.

타워가 해당 타일을 점유하면 효과가 적용되며, 타워가 제거되면 효과도
함께 제거된다. 현재 지원하는 실제 효과는 공격 사거리 증가이며,
향후 공격력 및 공격속도 효과로 확장할 수 있다.

다중 셀 타워는 점유한 타일의 효과를 스탯 및 적용 방식별 중첩 규칙에
따라 계산한다.

### 5.3 경영 영토 확장 — 미개척 영지

- 보유 영토(노란색) 기준 인접 영토(회색)만 선택 가능
- 웨이브 클리어 후 인접 영토 중 하나 선택 → 새로운 영토 확보 → 다음 확장 가능 영역 생성 (현재는 강제 1회, 이후 자원 소모형 전환 검토)
- **방향 전환**: 각 영토는 이제 고유 특수 효과를 주는 노드가 아니라, 확보 시 **새 자원을 생산하는 미개척 영지**다. 확보하면 그 영지 고유의 **새 자원 종류 + 생산 라인**이 해금된다(§3.2). 새 라인은 **주민 배치 없이 매일 정산 시 일정량이 자동 수급**된다.
- 자원 종류·해금 순서·영지별 정체성(테마)·영지별 일일 수급량은 TBD.

#### ✅ 기존 영토 효과 시스템 재편 완료 (#166)
종전 구현(영토마다 자원/주민/생산배율을 주는 **효과 SO 계층**: `TerritoryEffect`/`GrantResourceEffect`/`GainResidentEffect`/`ProductionMultiplierEffect`/`TerritoryEffectContext`)은 **#166에서 삭제**됐다. `TerritoryDefinition`은 "자원 영지 정의"(자원 종류 + 섬 프리팹 + 일일 수급 [Min,Max])로 교체됐고, 확보 즉시 지급 대신 **매일 정산 자동 수급**으로 동작한다(TerritoryGraph.md §5 참고). 초기 자원 4종: 금·루비·사파이어·다이아.

### 5.4 병사 배치

도입 여부가 아직 확정되지 않은 시스템이다. 만약 도입한다면 아래와 같은 방식을 고려 중이다:

- 웨이포인트에만 배치 가능, 배치 후 이동 불가
- 역할: 타워로 막지 못한 몬스터 저지
- 주민을 자원 생산 vs 병사 훈련 중 어디에 배치할지가 매일의 전략적 선택

#### ⚠️ 검토 중 이슈 (현재 논의 사항)

- **문제 ①**: 병사 배치와 스킬 시스템 간 차별성 부족
- **문제 ②**: 병사만의 전략적 역할이 부족
- **검토 방향 ①**: 스킬 시스템과 병사 시스템 통합 검토
- **검토 방향 ②**: 주민 배치 전략성을 자원 생산 축으로 통합
- **목표**: 병사 시스템은 "주민을 자원 생산과 병사 운용 사이에서 고민하게 만드는 것"이 핵심 목적임을 재확인

### 5.5 스킬 시스템

- 스킬 종류는 최소화 — 현재 고정 스킬 **1종** (#103 구현 완료)
  - **감전**: 스킬 버튼 클릭 → 범위 인디케이터가 마우스를 따라다님 → 원하는 위치를 클릭 → 그 범위의 몬스터에게 즉시 데미지
- **버프 스킬 제거됨 (#315)**: 한때 2번째 스킬로 "타겟팅 없이 즉시 발동, 모든 타워에 일정 시간 공격력/공속 배율"이 있었으나(WL-051에서 GDD 편입 확정, 2026-07-23), **조준도 타이밍 판단도 없어 "쿨 차면 누른다"가 유일한 최적 플레이**라 삭제했다. 스킬은 감전 1종으로 정리하고, 깊이는 보상 특수효과(§5.6) 축으로 낸다. 코드(`BuffSkillManager` 등 4개 파일)는 저장소에 남아있으나 씬에 배선돼 있지 않아 **미사용** — 되살리려면 기획 재검토가 선행돼야 한다
- 스킬 가짓수를 늘리기보다, 보상 시스템(§5.6)으로 기존 스킬에 특수 효과를 얹어 강화하는 방향
  - 구현 구조: 스킬은 시전 이벤트만 발행하고, 보상으로 획득한 특수 효과가 스스로 구독해 얹힌다 (상세: `Docs/Skill/PlayerSkill.md`)
- 마법 연구소(§5.7) 업그레이드 레벨은 감전의 **기본 스탯**(데미지·사거리·재충전 간격)을 레벨 비례로 배율 강화한다 — 보상 특수효과(위) 축과는 독립적으로 동시 스택 (#205, 상세: `Docs/Skill/PlayerSkill.md` §3.1)
- 연구소 레벨은 감전의 **착탄 이펙트**도 구간별로 더 화려한 것으로 교체한다 (#206) — 강화가 수치로만 오르지 않고 눈에 보이게 하려는 의도. 스킬은 **즉발형 그대로**이며, 하늘에서 떨어지는 연출처럼 이동+지연 데미지가 붙는 것은 보상 특수효과(§5.6) 쪽으로 넣는다 (상세: `Docs/Skill/PlayerSkill.md` §3.2)

### 5.6 보상 시스템

- 지급 시점: **매 웨이브 클리어 시 3택1** (#169 현행 구현). 이벤트성 지급(중간 보스 처치 등 특정 조건)으로의 전환은 TBD — 웨이브 트리거만 바꾸면 되는 구조라 조정 여지 있음
- 보상 내용은 스킬 개수를 늘리는 게 아니라 **보유한 스킬에 특수 효과를 부여**하는 것 (#169, 현재 **5종**)
  - 화상: 감전에 맞은 적에게 지속 피해(도트) — 효과가 **대상**을 따라다닌다
  - 폭탄: 감전 착탄 지점에 폭탄 설치 → 몇 초 뒤 범위 폭발
  - 추가시전: 감전의 **최대 충전 +1** (#319) — 감전은 쿨다운이 아니라 **충전(탄약)**을 쓴다. 충전이 남아 있으면 대기 없이 곧바로 다시 쏠 수 있고(총 1+레벨발), 재충전은 간격당 1발씩 채워지며 밤 시작에 만충으로 리셋된다. 예전의 "1클릭에 자동 반복 착탄"은 두 번째 착탄에 플레이어의 판단이 없어 폐기했다(§5.5 버프 스킬 삭제와 같은 축) — 레벨이 키우는 건 **밤 시작 연속 시전 횟수**이고, 매 발마다 새로 조준해야 한다
  - 전기장: 착탄 지점에 장판을 남겨 그 안에 있는 적에게 지속 피해 (#316) — 화상과 달리 **위치**에 결속돼, 적이 벗어나면 즉시 피해가 끊기고 다시 들어오면 재개된다. 대상을 노리는 게 아니라 **자리를 위협**하는 지역 거부(zone denial) 축
  - 처형: 감전에 맞은 적에게 **표식**이 2초 남고, 그 동안 체력이 임계(MaxHp 대비) 이하로 떨어지면 즉시 처형 (#318) — 화상·전기장·폭탄이 전부 **딜을 더 넣는** 축인 데 반해 처형은 **마무리** 축이다. 판정은 어떤 피해원이든 통과한다(타워 사격·화상 틱·전기장 틱·다른 감전), 그래서 단독으로는 약하고 **다른 보상·타워 화력과 조합될수록 강해진다**. 감전 자신의 피해도 판정 대상이라 감전 한 방으로 임계 아래까지 깎으면 그 자리에서 처형된다. **보스·중간보스는 대상에서 제외** — 처형은 긴 HP 바를 건너뛰는 메커니즘이라 보스전의 형태 자체를 없앤다
  - ~~버프 화상~~: 버프 스킬 제거(#315)와 함께 보상 풀에서 제외됐다. `BuffBurnReward.asset`·`WaveRewardType.BuffBurn`·`BurnBuff` 코드는 남아있으나 뽑히지 않는다
- 3개의 특수 효과 카드 중 하나를 선택하는 방식 (로그라이크 빌드 형성의 핵심 축)
- **같은 효과를 다시 선택하면 레벨업(중첩)** — 틱 데미지/폭발 데미지/발동 횟수/처형 임계가 레벨에 비례해 강해진다
- **효과별 최대 레벨 = 3** (#292). 상한에 도달하면 더 오르지 않고, 이후 웨이브의 보상 후보에서도 제외된다 — 골라도 아무 일이 없는 카드를 없애기 위함. 값은 각 효과 컴포넌트의 인스펙터가 소유한다(스킬 수치와 동일하게 CSV 미사용)
  - 상한값은 **보상 종류 수와 묶어서** 판단한다 — 종류가 (상한 + 3)보다 적으면 한 효과가 만렙에 닿는 순간 남은 카드가 매번 전부 제시돼 위의 "3택1"이 무너진다. 현재 **5종/상한 3**이라 필요 조건(6종)에 미달한다. 전기장 추가(#316) 전에는 3종/카드 3이라 **첫 웨이브부터 전부 제시**돼 선택이 아예 성립하지 않았고, 전기장으로 4종이 되며 그것이 해소됐다. 처형 추가(#318) 후 **5종 중 3장**이라, 한 효과가 Lv3에 닿아도 남은 4종 중 3장이 뽑혀 **선택이 계속 성립한다** — 붕괴 시점이 "만렙 1개"에서 "만렙 2개"로 밀렸다. 다만 밀린 것이지 사라진 것은 아니다. **보상 종류 확장으로 해소**할 계획이며(대체 보상으로 슬롯을 채우지 않는다 — 아래 항목), 1종을 더 추가하면 조건을 충족한다
- **보상 SO는 "무엇을" 주는지만 소유하고 "얼마나"는 받는 쪽(효과)이 소유한다** (#292) — 한 번 선택 = 1레벨 고정이고 증가폭은 각 효과의 레벨당 수치가 정한다. 보상 카드는 **전부 스킬 특수효과**이며, 마나석 같은 수량형 보상은 이 트랙에 들어오지 않는다(아래 별도 트랙 유지)
- 매 웨이브 클리어 시 지급되는 마나석(§4.3)과는 별도의 보상 트랙

### 5.7 건물 업그레이드

낮 동안 경영 공간에서 건물을 업그레이드해 성능을 강화한다.

- **이번 범위 — 기본 자원 생산 건물 3종**: **나무꾼의 집(나무) · 광산(철) · 농장(식량)**. 업그레이드 시 **주민당 획득 자원량이 증가**한다(주민 배치 생산량 = 주민당량 × 주민 수 → 주민당량↑). 이 3종만 이번 이슈에서 구현.
- **마법연구소(구현됨)**: 생산 라인이 아니라 **마나석으로 레벨만 올리는 업그레이드 전용 건물**로 구현. 강화 효과(스킬 강화)도 **구현 완료(#205/#206)** — 스킬 시스템이 연구소 레벨을 참조해 기본 스탯을 배율 강화하고 감전 착탄 이펙트를 교체한다(결합도 최소). 상세는 BuildingUpgrade.md §8, `Docs/Skill/PlayerSkill.md` §3.1~§3.2.
- **연금술사의 집 — 구현 완료(#229)**: 효과는 **교환 효율 개선**이다 — 지불 마나석은 그대로 두고 **받는 자원량을 배율로 늘린다**(§3.2). 단 **자체 업그레이드 버튼이 없다** — 종전 설계("마법연구소처럼 마나석으로 레벨을 올리는 건물")에서 바뀌어, 레벨 개념 없이 **본성 레벨이 곧 교환 효율**이다. 배율은 `BuildingAsset.Exchange.UpgradeLevels`(`RequiredCastleLevel` + `GainMultiplier`)에 authoring하며, 여기서 `RequiredCastleLevel`은 "본성 몇 레벨부터 이 배율"을 뜻한다.
- **본성 업그레이드 — 구현 완료(#229)**: 본성 레벨을 올리면 **하위 건물(생산 3종·마법연구소)의 업그레이드 Max 레벨이 해금**되고 연금술사 교환 효율이 오른다. 본성 SO는 **하위 건물을 알지 않는다** — 각 건물의 레벨 행이 `RequiredCastleLevel`(이 레벨이 열리는 데 필요한 본성 레벨)을 소유하므로, 건물이 추가돼도 그 건물 SO만 편집하면 된다. 같은 요구치를 여러 행에 붙이면 본성 한 단계가 하위 여러 레벨을 한꺼번에 연다 — 건물마다 다른 성장 속도가 데이터만으로 표현된다. 상세: BuildingUpgrade.md §9.
- **레벨·비용·증가폭 수치는 전부 TBD** — 구조부터 만들고 밸런싱 수치는 후속으로 확정.
- 미개척 영지 자원 라인의 업그레이드 지원 여부도 TBD(우선 기본 3종만).

> 기술 주의: 현재 건물 데이터는 건물 타입당 단일 SO(`BuildingAsset`)를 공유한다 — 인스턴스별 레벨 상태를 공유 SO에 쓰면 다른 인스턴스까지 오염된다(정적 조회 데이터 vs per-instance 상태 경계). 상세는 BuildingUpgrade.md·WatchList WL-016 참고.

### 5.8 타워 합성

전투 공간의 성장 축. 같은 타워를 계속 까는 대신, 설치한 타워들을 재료로 상위 타워를 만든다(#194 데이터 구조 / #195 실행 / #183 선택·패널 UI). **상세 명세는 진실의 원천 문서 `Docs/Core/TowerMerge.md`.**

- **레시피**: 재료 타워 종류(TowerID)별 필요 개수 → 결과 타워(+선택적 합성 추가 비용). SO(`TowerRecipe`)로 정의하며, 결과 타워는 별도 특수 타입이 아니라 일반 `TowerAsset`이다(신규 타워 종류로 추가 — §7).
- **매칭**: 포함 매칭 — 선택한 재료가 레시피의 필요 개수 이상이면 성립(여분 허용), 소모는 필요 개수만큼만.
- **선택·실행**: 설치 타워를 **Shift 클릭 또는 드래그 사각형**으로 복수 선택 → (2개 이상이면 합성 패널 표시) → 후보(결과) 타워 버튼 클릭 → 재료 타워 소모 + 합성 비용 지불 + 결과 타워를 기존 타워 배치와 동일하게 고스트로 타일에 배치. (Shift 클릭은 개별 토글, 드래그는 영역 선택 — MouseManager.md §5)
- **낮 전용**: 합성(멀티 선택·패널·실행)은 타워 배치와 같은 낮(배치) 페이즈 전용이다(밤 순간이동 방지, TowerMerge.md §10).
- **결과 배치 위치**: 제약 없음 — 건설 가능한 빈 타일이면 되고, **재료가 점유했던 자리도 포함**한다. 재료 소모가 후보 버튼 클릭 시점이라 배치를 시작할 때 그 타일이 이미 비어 있기 때문이다(#263 커맨드 패턴, TowerMerge.md §9). 배치를 취소하면 재료와 타일이 원래대로 돌아온다.
- 레시피 족보(재료 조합→결과)·합성 비용·재료 승계 등 밸런스·세부는 TBD(§8, TowerMerge.md §13).

### 5.8.1 타워 자가 성장 (램프업)

전투 공간의 **두 번째** 성장 축(#300). 합성(§5.8)이 "낮에 플레이어가 타워를 재료로 소모해 상위 타워를
만드는" 축이라면, 이쪽은 **밤에 타워가 싸운 실적으로 스스로 강해지는** 축이다. 플레이어 조작이 아니라
전투 결과가 입력이므로 두 축은 독립적으로 동시에 스택된다. **상세 명세는 `Docs/Core/Tower.md` §3.10.**

- **성장 조건 3종**: 명중할 때마다(공격 속도↑) · 적을 처치할 때마다(공격력↑) · 같은 대상을 계속
  조준한 시간(그 대상에게 주는 피해↑).
- **성장은 웨이브를 넘기지 않는다** — 웨이브 종료(밤→낮)에 모든 성장이 일괄 초기화된다. 근거 둘:
  ① Run 내내 누적되면 눈덩이가 되어 밸런싱이 후반 한 점에 묶인다 ② §5.9 저장이 성장분을 담지 않으므로
  "저장 후 이어하면 약해지는" 불일치가 생긴다. 웨이브 안으로 가두면 둘이 함께 사라진다.
- **정보 패널 표기**: 선택 시점의 현재 단계와 상한을 함께 보여준다(패널은 스냅샷이라 실시간 갱신은 없다).
- **획득 경로**: 성장형 3종은 전부 합성 전용이다 — 로스터·재료 조합은 `Docs/Core/TowerRoster.md`.
- 성장 폭·상한·감쇠 시간 등 수치는 TBD(§8). 특히 단일 조준형의 상한 피해와 사거리가 재검토 대상이다.

### 5.9 저장 / 이어하기

진행 중인 한 판을 낮 시작 시점에 자동 저장하고, 타이틀의 **이어하기**로 복원한다(#270). v1은 플레이 중 임의 시점의 스냅샷이 아니라 매일 낮이 시작된 직후의 확정 상태를 저장한다.

- **슬롯**: 플레이어 프로필 슬롯 3개를 제공하며 각 슬롯은 Run 저장 1개를 가진다. 슬롯별 `player.json`과 `run-save.json`을 독립 저장하고, 화면의 `세이브데이터 1`~`세이브데이터 3` 표시는 저장 문자열이 아니라 현재 언어와 슬롯 번호로 조립한다. 새 낮이 시작될 때 선택 슬롯의 Run 파일만 교체하므로 저장 파일이 날짜별로 쌓이지 않는다.
- **슬롯 선택**: 마지막 선택 슬롯을 기억해 게임 재실행 시 복원한다. 슬롯을 선택하지 않은 상태에서는 새 게임과 이어하기를 시작할 수 없다.
- **공통 설정**: 언어 등 게임 설정은 플레이어 슬롯과 무관한 공통 `settings.json`에 저장한다.
- **저장 시점**: 1일차 시작을 포함한 모든 `OnDayStart`. 밤 저장과 수동 저장은 v1 범위 밖이다.
- **저장 상태**: 클리어 웨이브 수와 낮 페이즈, 자원, 생산 건물 레벨·주민 배치, 업그레이드 건물 레벨, 증축 주민 수, 설치 타워 종류·셀 좌표, 보상 특수효과 중첩, 본진 HP, Run 마스터 시드와 시스템별 최종 사용 시드.
- **식별 방식**: 런타임 인스턴스와 인스펙터 배열 인덱스는 저장하지 않는다. 건물은 BuildingID, 타워는 TowerID 등 안정된 식별자로 기록하고 밸런스 수치는 복원 시 데이터 테이블과 SO에서 다시 읽는다.
- **맵 복원**: 전투맵과 버프 타일 전체를 저장하지 않고 시드로 동일하게 재생성한다. 저장된 웨이브까지 전투맵을 공개한 뒤 타워 배치 경로를 재사용해 타일 점유와 타일 버프까지 복원한다.
- **이어하기 노출**: 지원하는 버전의 정상 세이브가 있을 때만 타이틀에 버튼이 보인다. 세이브가 없거나 손상됐거나 현재 게임보다 높은 버전이면 숨긴다.
- **Run 종료**: 게임오버 또는 최종 승리 시 세이브를 삭제해 끝난 판으로 이어할 수 없게 한다.
- **포맷 호환성**: `{ version, data }` 구조로 버전과 내용을 분리한다. 향후 포맷 변경은 v1→v2→v3처럼 인접 버전 마이그레이션을 순차 적용한다.
- **구버전 이전**: 루트 경로의 기존 `run-save.json`은 선택 슬롯에 Run 저장이 없을 때만 이전하고, 대상 저장 성공 후 원본을 삭제한다.
- **메타 데이터**: `player.json`은 슬롯 ID·생성일·최근 플레이 시각만 저장하며, 언어에 종속된 표시 이름은 저장하지 않는다. 향후 업적·해금·누적 통계 같은 영구 진행 데이터가 추가되면 슬롯 폴더의 별도 `meta.json`에 저장하며, 슬롯 삭제 시 함께 삭제한다.
- **상세 계약**: 파일 구조, 버전 관리, 손상 처리와 마이그레이션 규칙은 `Docs/Core/SaveSystem.md`를 따른다.

## 7. 확장 가능성 (Scalability)

### 7.1 재현 가능한 Run 시드

- 새 게임을 시작할 때 Run을 대표하는 마스터 시드 하나를 확정한다.
- 전투맵과 영토 그래프는 마스터 시드에서 시스템별 고정 태그로 파생한 별도 시드를 사용한다.
- 같은 마스터 시드는 같은 전투맵 경로·지형·버프 타일과 같은 영토 그래프를 만든다.
- 일반 새 게임은 매 Run 새로운 마스터 시드를 만들어 리플레이 다양성을 유지한다.
- 저장/로드는 맵 타일 전체가 아니라 마스터 시드와 시스템별 최종 사용 시드를 저장해 동일한 Run을 복원한다(#270 구현 완료, §5.9).
- 결과 화면의 시드 표시·복사 기능과 웨이브/보상 난수 파생은 후속 작업이다.
- Play 검증(2026-08-04): 같은 입력 시드의 결과 동일성과 일반 새 게임의 매 Run 랜덤화를 확인했다.

- 확장팩 — 몬스터 종류 추가
- 확장팩 — 타워 종류 추가 (단일/광역/연쇄/마법타워·버프·디버프 5종 데이터 설계 완료, haste_tower처럼
  타워가 타워를 버프하는 지원 타워 개념 포함 — WL-026)
- 스킬 테크트리 확장
- 경영 영토 패시브 다양화를 통한 빌드 확장
- 타워 합성 족보 확장 — 재료 조합·결과 타워 추가(§5.8, #194/#195 구현)
