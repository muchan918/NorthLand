## 1. 목표 룩 · 원리

**오쏘그래픽 카메라(확정) + 셰이더로 "움직이는 미니어처(디오라마)" 착시**를 만든다(2.5D보다 미니어처 우선 — 팀 결정).

실사 미니어처 착시는 사진학적으로 잘 알려진 조합이며, 효과 기여도 순으로:

| 순위 | 요소 | 기여도(체감) | 원리 |
|---|---|---|---|
| 1 | **틸트-시프트 블러** | ~50% | 좁은 포커스 밴드 + 상하 블러 = "접사로 찍은 작은 물체" 착시의 본체 |
| 2 | **컬러 그레이딩** | ~25% | 채도↑·대비↑·따뜻한 톤 = 장난감/점토 특유의 쨍한 색감 |
| 3 | **라이팅** | ~15% | "책상 스탠드" 같은 강한 단일 키 라이트 + 또렷한 그림자 |
| 4 | **SSAO·비네트** | ~10% | 접지 그림자가 "작은 물체" 스케일감, 비네트가 "탁상 위 디오라마" 프레임감 |
| - | 오브젝트 셰이더(툰) | 보조 | 형태 가독성·색 단순화 보조. 미니어처 필의 본체는 위 1~4 — Flat Kit 툰 머티리얼 |
| - | 아웃라인 | 보조 | 전역 잉크 라인으로 오브젝트 분리감·"칠한 미니어처" 느낌 보강. Flat Kit Outline 렌더러 피처(스크린 스페이스) |

## 2. 확정 결정 (팀 결정, 2026-07-21 — 이슈 #148)

1. **오쏘그래픽 카메라 확정.** 룩 전체의 전제 — 아래 결정은 모두 오쏘를 전제로 한다.
2. **틸트-시프트 = 스크린 Y 밴드 방식(자작 풀스크린).** URP 빌트인 DoF는 **오쏘 카메라 미지원**(공식 문서 명시)이라 제외.
   화면 세로축 기준 포커스 밴드 + 상/하 그라데이션 블러 — 원조 틸트-시프트 사진과 동일 원리이며
   고정 쿼터뷰 구도에 최적, 아트 컨트롤(밴드 위치/폭/강도) 용이.
3. **오브젝트 셰이딩 + 아웃라인 = Flat Kit**(에셋 스토어 `Flat Kit: Toon Shading and Water`, `Assets/Imported/` 벤더 배치).
   근거: Unity 6000.3/URP 17.3 지원 범위 안 + **활발한 유지보수**(v4.9.11, 2026-06 — 공식 툰 셰이더의 방치 리스크 회피),
   아웃라인이 **URP 렌더러 피처(스크린 스페이스)**라 우리가 원한 전역 방식이면서 틸트-시프트와 같은 계열. 물 셰이더도
   포함되나 muchan `WaterURP_Ortho`가 이미 있어 **미사용**. 남은 검증: **오쏘 카메라에서 Flat Kit 아웃라인 거동**만 스파이크(§8).
4. **아웃라인 범위 = 전역 라인 우선.** Flat Kit Outline 렌더러 피처로 모든 오브젝트에 잉크 라인.
   #138 선택 강조(상호작용 건물만 도드라지게)는 이 전역 라인 **위에 per-object/레이어**로 얹는 후속 작업.
5. **일단 PC 파이프라인만 적용.** CLAUDE.md "PC/Mobile 양쪽 적용" 규칙의 **명시적 예외**(플랫폼 특정 결정).
   모바일 프리셋(저품질 블러 또는 그레이딩만)은 별도 후속 이슈로 분리.

## 3. 아키텍처 — 레이어 구성

적용 순서 = 의존 순서. 각 레이어는 독립적으로 켜고 끌 수 있어야 한다(튜닝·디버깅·성능 비교).

### 3.1 룩 볼륨 (포스트프로세싱)
- 전역 Volume 프로파일 신설: **Color Adjustments**(채도 +15~25 TBD·대비·따뜻한 톤), **Tonemapping**, **Vignette**(약하게).
- 셰이더 작업 0 — 빌트인 컴포넌트만. 수치는 전부 **튜닝 TBD**(§8).
- ⚠️ `Assets/Settings/DefaultVolumeProfile.asset`에 템플릿 잔재(`CopyPasteTestComponent2` 등 유니티 테스트용
  컴포넌트) 발견됨 — 정리 검토 대상(§8).

### 3.2 틸트-시프트 풀스크린 패스
- **Fullscreen Shader Graph**(스크린 Y 그라데이션 블러) + **Full Screen Pass Renderer Feature**를
  `PC_Renderer`에 등재. Unity 6 URP 내장 기능이라 커스텀 C# 렌더러 피처 불필요 예상(검증 TBD).
- 노출 파라미터: 포커스 중심(스크린 Y 0~1) · 밴드 폭 · 최대 블러 강도 · 샘플 수.
- 경영/전투 공간의 카메라 구도가 달라 밴드 튜닝 값이 다를 수 있음 — 공간별 파라미터 전환 필요 여부 TBD(§8).

### 3.3 라이팅 프리셋
- "책상 스탠드" 콘셉트: 강한 단일 키 디렉셔널 + 또렷한 그림자(PC 소프트 섀도 유지) + 정리된 앰비언트.
- `DayNightLightingController`(WL-020)와 **역할 분리**: 룩 볼륨·틸트-시프트는 **페이즈 무관 전역 상수**,
  낮/밤 전환은 **라이트 색·강도·앰비언트만** 변경. 낮/밤 전환이 룩 볼륨을 건드리지 않는다.
- WL-020의 전역 RenderSettings 변경(앰비언트 모드·스카이박스 교체)과 충돌 여부 확인 필수.

### 3.4 오브젝트 툰 셰이딩 (Flat Kit)
- Flat Kit 툰(그라데이션 램프) 머티리얼로 오브젝트 셰이딩. Flat Kit 본체는 `Assets/Imported/`(벤더).
- 미니어처 필 유지 가이드: **소프트 램프**(급격한 2단 셀 컷 지양) + **그림자 수용(Receive Shadows) 유지**.
  급한 셀 컷은 "만화" 감성으로 이동해 목표 룩과 어긋난다.
- 적용 절차: 파일럿 3종(건물 1·유닛 1·지형 1) → 팀 스크린샷 컨펌 → 전면 이관.
- ⚠️ `Assets/Imported/` 원본(Flat Kit 셰이더·샘플 포함) 직접 수정 금지 — 우리 머티리얼은 **Flat Kit 셰이더를 참조하는 별도 머티리얼 에셋**으로 만들어 오브젝트에 적용(벤더 원본 밖).

### 3.5 아웃라인 (Flat Kit Outline 렌더러 피처)
- Flat Kit **Outline 렌더러 피처**를 `PC_Renderer`에 등재 — 스크린 스페이스(깊이/노멀 에지) 전역 라인. `Fade With Distance` 등 파라미터 노출.
- **틸트-시프트와의 순서**: 아웃라인 → 틸트-시프트 순으로 배치하면 초점 밖(위/아래) 라인도 함께 흐려져 미니어처 필이 강화된다(권장).
- **오쏘 거동 확인 필요**(§8): 스크린 스페이스 아웃라인은 깊이 버퍼 기반이라 오쏘(선형 깊이)에서 임계값 튜닝이 다를 수 있음. 카메라 자체는 오쏘 확정이나, Flat Kit 아웃라인이 오쏘에서 의도대로 뜨는지는 별개 검증.
- **#138 선택 강조**는 이 전역 라인 위에 per-object/레이어 마스크로 얹는 후속(별 이슈).

## 4. 통합 계약 (기존 시스템 접점)

| 접점 | 방식 |
|---|---|
| **카메라** | 오쏘그래픽 **확정**(프로젝트 결정, GameScene 확인됨). 카메라 2개 병존(WL-023: `CameraController`/`CameraController2`) — 포스트프로세싱은 카메라별 활성 플래그라 **양쪽 카메라의 Post Processing 활성 상태 점검** 필요 |
| **낮/밤** | `DayNightLightingController`(WL-020)와 §3.3 역할 분리 준수 — 룩은 전역 상수, 낮/밤은 라이트만 |
| **SSAO** | `PC_Renderer`에 기활성 — 유지하되 강도만 룩에 맞춰 조정 |
| **렌더러 피처 순서** | `PC_Renderer`에 Flat Kit Outline + 자작 틸트-시프트가 공존 — 아웃라인이 틸트-시프트보다 **먼저**(초점 밖 라인도 블러) 오도록 순서 관리(§3.5). Flat Kit Fog/Pixellation 등 다른 피처는 사용 시에만 추가 |
| **기존 커스텀 비주얼** | muchan 물 셰이더(`WaterURP_Ortho`, **Flat Kit 물은 미사용**) · 영토 소용돌이(`VortexVisual`) · 배 연출(#93)과 톤 충돌 확인 — 특히 틸트-시프트 블러 밴드·전역 아웃라인에 물/파티클이 걸릴 때 아티팩트 검증 |
| **벤더 에셋(Flat Kit)** | Flat Kit을 `Assets/Imported/`에 벤더 배치(유료 $39.90·Asset Store 시트당 라이선스). 원본 무수정(저장소 규칙) — 우리 머티리얼은 Flat Kit 셰이더 참조 **복제본**으로, Outline 등 렌더러 피처는 `PC_Renderer`(Settings)에 등재하는 우리 config |
| **파이프라인 에셋** | PC 전용(§2 결정 5). Flat Kit 렌더러 피처(Outline 등)·틸트-시프트는 `PC_Renderer`에만 등재. `Mobile_RPAsset`/`Mobile_Renderer`는 이번 범위 변경 없음 — 후속 이슈에서 프리셋 분기 |

**SystemMap 등재**: 구현 착수 후 렌더러 피처·셰이더·프로파일이 실제로 생기면 `Docs/Review/SystemMap.md`에
시스템 행·접점을 등재한다(코드 없는 현재는 미등재 — 문서-구현 일치 원칙).

## 6. 검증 방법

- 테스트 스위트 부재(프로젝트 공통) — **에디터 스크린샷 비교**(`unity-cli screenshot`)로 단계별 전/후를 남기고
  팀 육안 컨펌. 경영/전투 공간 각각 1장 이상.
- 컴파일·씬 에러는 `unity-cli`로 확인(가이드 문서 준수).
- 성능: PC 기준이므로 1차에서는 프레임 예산 측정 생략(모바일 후속 이슈에서 필수).

## 7. 로직/뷰 분리 관점

이 계층은 **전부 뷰**다 — 게임플레이 상태(모델)를 읽지도 쓰지도 않는다. 낮/밤 페이즈 이벤트조차 직접 구독하지
않고(§3.3 역할 분리), 룩 파라미터는 에셋(프로파일·머티리얼)에만 존재한다. 따라서 이 계층의 어떤 변경도
게임플레이 코드 리뷰 대상이 아니며, 반대로 게임플레이 변경이 이 계층을 깨뜨리지도 않는다.
