## 다음 빌드 때 할 것

이번 빌드의 방향은 **"게임의 형태 갖추기"** 다. 빌드 3까지 핵심 시스템은 대부분 들어갔으므로, 이번에는 (1) 게임으로서 갖춰야 할 기본기(설정 · 튜토리얼 · 세이브 · UI 에셋)를 채우고, (2) 지금 구조가 애매한 부분(자원 · 영토)을 개편하며, (3) 매 판이 달라지도록 랜덤성을 넣는다.

> 아래 항목 중 설정 · 튜토리얼 · 세이브/로드는 GDD에 명세가 없다 — 구현과 함께 GDD에 해당 절을 신설하고 §8 체크리스트를 갱신할 것.

### 1. 설정

현재 설정 패널에는 **언어 변경 · 타이틀로 · 게임 종료**만 있다(`Assets/Scripts/SettingUI/SettingUI.cs`). 게임에 필요한 설정을 추가한다.

- **게임플레이 편의**
  - 카메라 이동 · 줌 감도
  - 데미지 표시, 사거리 상시 표시 등 토글 (여유 시)
- **설정 값 영속화** — 현재 언어만 `PlayerPrefs`에 저장된다. 나머지 설정도 같은 방식으로 저장하고 게임 시작 시 일괄 적용한다.
- 설정 패널은 **타이틀 씬과 인게임 양쪽에서 동일하게** 동작해야 한다(`SettingUI`가 이미 양쪽 겸용 구조).

### 2. 튜토리얼

처음 켠 플레이어가 낮/밤 두 공간과 경영 → 배치 → 방어 흐름을 이해하지 못한다. 첫 판을 안내한다.

- **범위**: 1일차 낮 ~ 웨이브 1 클리어까지. 이후 씬 새로 시작
- **진행 순서**
  1. 영토 확장 — 확장 가능한 노드 강조 → 클릭 유도
  2. 주민 배치 — 생산 라인 강조 → 배치 유도
  3. 건물 클릭 → 업그레이드
  4. 낮 종료
  5. 타워 배치 — 타워 패널 강조 → 배치 가능 타일 강조
  6. 밤 시작 → 스킬 시전 유도
  7. 웨이브 클리어 → 보상 선택 유도
- **연출 요소**
  - 딤(dim) 오버레이 + 대상만 하이라이트, 대상 외 입력 차단
  - 말풍선 / 안내 텍스트 — 로컬라이제이션 테이블(ko / en / ja)에 등록
  - 단계 완료 조건은 각 시스템의 기존 이벤트를 구독해 판정(임의 타이머 금지)
- **스킵 / 재시청** — 최초 1회 자동 실행(`PlayerPrefs` 플래그), 언제든 스킵 가능, 설정 패널에 "튜토리얼 다시 보기"
- **데이터화** — 단계 목록(강조 대상 · 문구 키 · 완료 조건)을 SO 또는 CSV로 빼서 코드 수정 없이 순서를 바꿀 수 있게 한다.

**결정 필요**

- 강제 유도(다음 단계 전까지 다른 조작 차단) vs 안내만 띄우고 자유 조작 허용
- 튜토리얼 전용 고정 맵 · 고정 시드를 쓸 것인가, 일반 게임 위에 얹을 것인가
- 튜토리얼 중 본진이 파괴됐을 때의 처리

### 3. 세이브 / 로드

게임을 끄면 진행이 전부 사라지고, 타이틀로 나가면 초기화된다. 이어하기를 만든다.

- **저장 대상(전체 게임 상태)**
  - 진행: 현재 일차 · 웨이브 번호 · 낮/밤 페이즈
  - 경영: 자원 보유량, 확보한 영토, 건설된 건물과 레벨, 주민 배치, 본진 레벨 · HP
  - 전투: 설치된 타워의 종류 · 위치 · 상태
  - 성장: 스킬 레벨(마법 연구소), 웨이브 보상 특수효과 및 중첩 레벨
  - **모든 랜덤 시드** — 아래 항목 참조
- **랜덤 시드 데이터화 (§8과 직결)**
  - 지금 시드가 코드/인스펙터에 흩어져 있다. 전투맵은 `CombatMapGenerator`의 `seed = 12345` 고정, 영토는 `TerritoryController._seed`가 0이면 매판 랜덤이라 **재현이 불가능하다**.
  - 판 시작 시 **마스터 시드 1개**를 뽑고, 각 시스템 시드는 거기서 파생시킨다(전투맵 · 버프 타일 · 영토 그래프 · 웨이브 구성 · 보상 풀).
  - 마스터 시드를 세이브에 저장 → 로드 시 같은 맵 · 같은 영토 · 같은 보상이 재현되어야 한다.
  - 맵을 타일 통째로 저장하지 않고 **시드만으로 복원**하는 것이 목표. 단 생성이 완전 결정적이어야 성립한다(전투맵은 실패 시 시드를 바꿔 재시도하는 fallback이 있으므로 **최종 사용 시드**를 저장할 것).
  - 시드는 디버그 패널에 표시하고, 직접 입력해 같은 판을 다시 돌릴 수 있게 한다(밸런스 테스트용).
- **저장 방식**
  - JSON(`JsonUtility` 또는 Newtonsoft) → `Application.persistentDataPath`
  - **버전 필드 필수** — 포맷이 바뀌었을 때 구 세이브를 무시/마이그레이션할 수 있어야 한다
  - 세이브에는 인스턴스가 아니라 **ID(타워 · 건물 · 자원 종류)** 만 담고 복원 시 DataTable에서 재조회 — 밸런스 수치가 바뀌어도 구 세이브가 깨지지 않게
- **저장 시점** — 자동: 낮 시작 시점(페이즈 경계라 몬스터·투사체 같은 휘발 상태가 없음) / 수동: 설정 패널
- **로드 진입점** — 타이틀에 "이어하기" 추가(세이브 없으면 비활성), 게임 오버 · 클리어 시 세이브 처리

- **에셋 선정** — 게임 콘셉트(북쪽 마을 · 디저트 톤)에 맞는 UI 킷 확정. `Assets/Imported/`에 벤더링.
- **적용 대상 전수**

  - 경영: 건물 정보 · 업그레이드 패널, 본진 패널, 마법 연구소, 연금술사 상점
  - 전투: 타워 패널, 타워 정보 패널, 합성 패널, 스킬 슬롯 · 쿨타임
  - 기타: 타이틀, 설정, 보상 선택, 게임 오버 / 클리어, 미니맵 프레임
- **아이콘** — 자원, 타워, 건물, 스킬, 상태이상(스턴 · 슬로우) 아이콘 정비 (자원 아이콘은 §6 개편 확정 후)

### 5. 타워 합성 — 드래그 복수 선택

현재 합성 재료는 **Shift + 클릭으로 한 개씩** 골라야 한다. 여러 개를 고를 때 클릭 수가 많고 번거롭다. **드래그로 범위를 훑어 한 번에 선택**할 수 있게 한다.

- **박스 드래그 선택** — 빈 곳에서 좌클릭을 누른 채 끌면 선택 박스가 그려지고, 놓는 순간 박스 안에 들어온 타워가 전부 합성 선택된다.
  - 선택 대상은 기존과 동일하게 `IGroupSelectable`을 가진 것(= 설치된 타워)만. 건물 · 영지 노드 등은 박스에 들어와도 무시한다.
  - Shift를 누른 채 드래그하면 **기존 선택에 추가**, 그냥 드래그하면 **새로 선택**(기존 선택 해제)
  - 드래그 중 박스 안에 들어온 타워는 실시간으로 초록 아웃라인이 미리 표시되면 좋다
- **기존 Shift + 클릭은 유지** — 한두 개만 고르거나 특정 타워만 빼는 데 여전히 필요하다. 드래그는 대안 수단으로 추가하는 것.
- **입력 판정 정리** — 좌클릭이 지금 "단일 선택 / Shift 추가 선택"에 이미 쓰이고 있다. 누른 지점에서 **일정 픽셀 이상 움직였을 때만** 드래그로 판정하고, 그 미만이면 기존 클릭 동작으로 처리한다(임계값 확정 필요).
- **해제 규칙 유지** — 빈 곳 클릭 · Esc · 밤 전환 시 선택 초기화(WL-085 경로)가 드래그로 선택한 경우에도 동일하게 동작해야 한다.
- 카메라 이동이 우클릭 드래그이므로 좌클릭 드래그와 충돌하지 않지만, 미니맵 · UI 위에서 시작한 드래그는 무시되는지 확인할 것.

### 6. 자원 개편

현재 자원은 `ResourceKind` 8종(나무 · 철 · 식량 · 마나 + 금 · 루비 · 사파이어 · 다이아)인데, **어떤 자원이 어디에 쓰이는지가 불분명하다.** 특히 특수 자원 4종은 수급 경로(영토)만 있고 소비처가 뚜렷하지 않다.

- **소비처 매트릭스 확정** — 자원 × 사용처 표를 만들어 GDD에 싣는다.
  - 사용처: 타워 배치 · 타워 합성 · 건물 건설 · 건물 업그레이드 · 본진 업그레이드 · 스킬 업그레이드 · 연금술사 교환
  - 각 칸에 어떤 자원을 얼마나 쓰는지 명시. **소비처가 없는 자원은 만들지 않는다.**
- **역할 분리** — 기본 자원(상시 수급, 저렴한 반복 소비) / 마나석(웨이브 보상, 성장 통화) / 특수 자원(영토 확보 보상, 고급 해금 전용)이 서로 겹치지 않게 한다.
- **특수 자원 4종의 용도 부여** — 상위 타워 합성 재료, 고레벨 업그레이드 요구치 등으로 소비처를 만든다.
- **이름 · 아이콘 개편** — 에셋 톤에 맞게(나무 · 철 → 사탕 · 초콜릿 등). `ResourceKind` enum 값 순서는 직렬화 인덱스 때문에 **변경 금지** — 표시 이름은 `NameKey`(로컬라이제이션)로만 바꾸고, 3개 언어 모두 갱신할 것.
- **수급/소비 밸런스 재점검** — 개편 후 자원별 하루 수급량 대비 소비량 확인.

**결정 필요**

- 자원 종류를 8종 그대로 갈 것인가, 줄일 것인가
- 특수 자원 4종을 각각 다르게 쓸 것인가, 하나의 "고급 자원"으로 묶을 것인가
- 새 이름 목록(ko / en / ja)

### 7. 영토 개편

현재 영토는 절차적으로 생성된 그래프(`TerritoryGraphGenerator`)에서 인접 노드를 확보하면 해당 영지의 고유 자원이 **매일 자동 수급**되는 구조다. 확보 외에 할 수 있는 일이 없다.

- 손볼 후보
  - 영토마다 성격 부여 — 자원 종류·양뿐 아니라 특수 효과(생산 보너스 · 방어 · 해금 등)
  - 확보 이후의 상호작용 — 영토 자체를 개발/업그레이드할 수 있는지
  - 확보 비용과 조건 — 현재는 인접이면 확보 가능. 자원 소모 · 일차 제한 · 웨이브 클리어 요구 등
  - 전투 공간과의 연결 — 확보한 영토가 전투에 미치는 영향(현재는 없음)
  - 그래프 생성 규칙 — 노드 수 · 분기 · 거리, 판마다 얼마나 달라질지(§8과 연동)
  - 시각적 표현 — 확보/미확보/확보 가능 상태 구분

### 8. 게임 랜덤화

지금은 전투맵 시드가 `12345`로 고정이라 **매 판 같은 맵**이 나온다. 판마다 다른 게임이 되게 한다.

- **랜덤화 대상**
  - 전투맵 지형 · 경로 (현재 고정)
  - 버프 타일 위치 · 수치 (빌드 3 테스트에서 매판 동일 확인 — ❌)
  - 영토 그래프 배치와 영지 종류 (현재 `_seed = 0`이면 랜덤이지만 재현 불가)
  - 웨이브 구성 — 몬스터 조합 · 스폰 순서
  - 웨이브 클리어 보상 후보

**결정 필요**

- 어디까지 랜덤으로 할 것인가 — 맵·타일만인가, 웨이브 구성과 보상까지인가
- 난이도 하한/상한을 어떻게 보장할 것인가(생성 후 검증 기준)
