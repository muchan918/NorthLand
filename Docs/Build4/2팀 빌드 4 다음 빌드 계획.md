## 다음 빌드 때 할 것

이번 빌드의 방향은 **"처음 켠 사람이 이해할 수 있는 게임"** 이다. 시스템은 대체로 들어갔고 한 판이 재현 · 영속되지만, 화면은 여전히 기본 UI이고 아무 안내가 없어 무엇부터 해야 하는지 알 수 없다. 이번에는 (1) 플레이어에게 게임을 설명하는 층(튜토리얼 · 설정 · UI 에셋)을 올리고, (2) 빌드 4에서 이월된 구조 개편(자원 · 영토)을 처리하고, (3) 랜덤화와 밸런스의 남은 구멍을 메운다.

> 아래 항목 중 **튜토리얼 · 설정 확장**은 GDD에 명세가 없다 — 구현과 함께 GDD에 해당 절을 신설할 것.
> §1~§3은 빌드 3 계획 §1 · §2 · §4에서 **두 번째로 이월**된 항목이다. 이번에도 밀리면 범위를 줄여서라도 착수 여부를 먼저 정할 것.

### 1. 튜토리얼

처음 켠 플레이어가 낮/밤 두 공간과 경영 → 배치 → 방어 흐름을 이해하지 못한다. 첫 판을 안내한다.

- **범위**: 1일차 낮 ~ 웨이브 1 클리어까지
- **진행 순서**: 영토 확장 → 주민 배치 → 건물 클릭·업그레이드 → 낮 종료 → 타워 배치 → 밤 시작·스킬 시전 → 웨이브 클리어·보상 선택
- **연출 요소** — 딤 오버레이 + 대상만 하이라이트, 대상 외 입력 차단, 말풍선(로컬라이제이션 ko/en/ja 등록)
- 단계 완료 조건은 각 시스템의 **기존 이벤트를 구독해 판정**한다(임의 타이머 금지)
- **스킵 / 재시청** — 최초 1회 자동 실행(`PlayerPrefs` 플래그), 언제든 스킵, 설정 패널에 "튜토리얼 다시 보기"
- **데이터화** — 단계 목록(강조 대상 · 문구 키 · 완료 조건)을 SO 또는 CSV로 분리
- **시드 활용** — 빌드 4에서 마스터 시드 직접 입력이 들어갔으므로 **튜토리얼 전용 고정 시드**로 고정 맵을 쓸 수 있다. 별도 튜토리얼 맵을 만들 필요가 없어졌다

**결정 필요**
- 강제 유도(다음 단계 전까지 다른 조작 차단) vs 안내만 띄우고 자유 조작 허용
- 튜토리얼 중 본진이 파괴됐을 때의 처리
- 튜토리얼 진행 중 자동 저장 · 이어하기와의 관계

### 2. UI 에셋 적용

기능은 다 있지만 화면이 기본 Unity UI라 게임처럼 보이지 않는다. 빌드 4에서 **본진 룩(툰 셰이딩)이 확정됐으므로 UI 톤의 기준이 생겼다.**

- **에셋 선정** — 확정된 툰 룩 · 디저트 톤에 맞는 UI 킷. `Assets/Imported/`에 벤더링
- **적용 대상 전수**
  - 공통: 패널 배경 · 버튼 · 슬라이더 · 토글 · 스크롤바
  - HUD: 자원 바, 일차 · 웨이브 표시, 배속 버튼, 본진 HP, **Undo 버튼**
  - 경영: 건물 정보 · 업그레이드 패널, 본진 패널, 마법 연구소, 연금술사 상점
  - 전투: 타워 패널, 타워 정보 패널, 합성 패널, **합성 족보 패널**, 스킬 슬롯 · 쿨타임
  - 기타: 타이틀(**이어하기 · 시드 입력 포함**), 설정, 보상 선택, 게임 오버 / 클리어, 미니맵 프레임
- **아이콘** — 자원, **타워 15종**, 건물, 스킬, 상태이상(스턴 · 슬로우 · 화상 · 독) (자원 아이콘은 §4 확정 후)
- **폰트** — 게임 톤에 맞게 교체. **ko / en / ja 글리프를 모두 포함**하는지 확인
- **레이아웃 정리** — 기준 해상도 · Canvas Scaler Match 값 통일, 렌더 순서 재점검

### 3. 설정 확장

현재 설정 패널에는 **언어 변경 · 타이틀로 · 게임 종료**만 있다.

- **오디오** — 마스터 / BGM / SFX 볼륨 (오디오 도입과 세트, §7)
- **게임플레이 편의** — 카메라 이동 · 줌 감도, 데미지 표시 · 사거리 상시 표시 토글(여유 시)
- **수동 저장 / 불러오기** — 빌드 4는 낮 시작 자동 저장뿐이다. 설정 패널에서 수동 저장을 열지 결정
- **설정 값 영속화** — 현재 언어만 `PlayerPrefs`에 저장된다. 나머지도 같은 방식으로 저장하고 시작 시 일괄 적용
- 타이틀 씬과 인게임 양쪽에서 동일하게 동작해야 한다

### 4. 자원 개편

`ResourceKind` 8종(나무 · 철 · 식량 · 마나 + 금 · 루비 · 사파이어 · 다이아)인데 **어떤 자원이 어디에 쓰이는지가 불분명하다.** 특수 자원 4종은 수급 경로(영토)만 있고 소비처가 뚜렷하지 않다. 빌드 3에서 이월된 항목이며, **빌드 4에서 타워가 15종으로 늘고 합성 전용이 8종이 되면서 소비처 설계 여지가 커졌다.**

- **소비처 매트릭스 확정** — 자원 × 사용처(타워 배치 · 타워 합성 · 건물 건설 · 건물 업그레이드 · 본진 업그레이드 · 스킬 업그레이드 · 연금술사 교환) 표를 만들어 GDD에 싣는다. **소비처가 없는 자원은 만들지 않는다.**
- **역할 분리** — 기본 자원(상시 수급, 저렴한 반복 소비) / 마나석(웨이브 보상, 성장 통화) / 특수 자원(영토 보상, 고급 해금 전용)이 겹치지 않게
- **특수 자원 4종의 용도 부여** — **합성 전용 상위 타워의 추가 비용**이 유력한 자리다(현재 합성 전용 8종은 전부 `Cost:[]`)
- **이름 · 아이콘 개편** — 에셋 톤에 맞게. `ResourceKind` enum 값 순서는 직렬화 인덱스 때문에 **변경 금지** — 표시 이름은 `NameKey`로만 바꾸고 3개 언어 갱신
- **세이브 스키마 영향 확인** — 자원은 절대값으로 저장된다. 종류를 줄이면 구 세이브 마이그레이션이 필요하다

**결정 필요**
- 자원 종류를 8종 그대로 갈 것인가, 줄일 것인가
- 특수 자원 4종을 각각 다르게 쓸 것인가, 하나의 "고급 자원"으로 묶을 것인가
- 새 이름 목록(ko / en / ja)

### 5. 영토 개편

확보하면 고유 자원이 매일 자동 수급되는 것 외에 할 수 있는 일이 없다. 빌드 3에서 이월.

- 손볼 후보
  - 영토마다 성격 부여 — 자원 종류 · 양뿐 아니라 특수 효과(생산 보너스 · 방어 · 해금 등)
  - 확보 이후의 상호작용 — 영토 자체를 개발/업그레이드할 수 있는지
  - 확보 비용과 조건 — 현재는 인접이면 확보 가능. 자원 소모 · 일차 제한 · 웨이브 클리어 요구 등
  - 전투 공간과의 연결 — 확보한 영토가 전투에 미치는 영향(현재는 없음)
  - 그래프 생성 규칙 — 노드 수 · 분기 · 거리(빌드 4에서 시드 연결은 끝났으므로 생성 규칙만 남았다)
  - 시각적 표현 — 확보/미확보/확보 가능 상태 구분
- **세이브 영향** — 영토는 노드 ID로 저장된다. 생성 규칙을 바꾸면 같은 시드에서도 ID 대응이 달라질 수 있으니 마이그레이션 여부 확인

### 6. 랜덤화 잔여 · 밸런스

빌드 4에서 **전투맵 · 영토는 마스터 시드에 연결됐다.** 남은 대상을 마무리하고 난이도 하한/상한을 정한다.

- **남은 랜덤화 대상**
  - **버프 타일 위치 · 수치** — 파생 시드 연결 안 됨. 빌드 3부터 ❌ 로 남아 있는 항목
  - 웨이브 구성(몬스터 조합 · 스폰 순서), 웨이브 클리어 보상 후보
- **밸런스**
  - 타워 15종 스탯 전수 카탈로그 작성 + 역할 중복 정리
  - 합성 족보 확정(GDD §5.8 TBD) — 합성 추가 비용과 §4 특수 자원 연결
  - 웨이브 수 확정 및 맵 공개 분모 통일 (WL-150)
  - `lightning_tower` 획득 경로 배선 또는 폐기 결정
  - 직접배치 로스터 축소 사인오프 (WL-156)

**결정 필요**
- 웨이브 구성 · 보상까지 랜덤화할 것인가, 맵 · 타일만 둘 것인가
- 난이도 하한/상한을 어떻게 보장할 것인가(생성 후 검증 기준)

### 7. 오디오

전무하다. 룩이 확정되고 UI 킷이 들어가는 시점이 맞춰 넣기 좋다.

- BGM — 낮 / 밤 2트랙 최소, 페이즈 전환 시 크로스페이드
- SFX — 타워 배치 · 합성 · 되돌리기, 타워 발사 · 명중, 몬스터 사망, 스킬 시전, 버튼 · 패널 열림, 웨이브 클리어 / 게임 오버
- 볼륨 설정(§3) · `AudioMixer` 그룹 구성, 배속 상태의 피치 처리 방침
- 에셋 조달 및 라이선스 확인

### 8. 주민 후속

빌드 4에서 주민이 살기 시작했다. 남은 축은 조작과 밀도다.

- **드롭 배치** — 주민을 들어서 생산 건물에 떨어뜨려 배정하는 조작(현재는 패널 `+`/`-` 만). `AssignVillager`가 `void`라 성공 여부를 알 수 없는 계약 문제 선행 해결 필요
- **밀도 의존 수치 5종 재실측** — 정본 씬 기준으로. 춤이 사문화됐는지 먼저 확인 (WL-153)
- **주민 정보 패널** 착수 전 선택 상한의 의미 정리 (WL-158)
- 후속 콘텐츠 후보 — 직업 · 공연 · 구경(R13/R14)
