## 다음 빌드 때 할 것

이번 빌드의 방향은 **"콘텐츠를 늘리고, 절반만 끝난 것을 마무리한다"** 이다. 시스템은 대체로 들어갔고 한 판이 재현 · 영속되지만, **룩과 UI가 절반만 적용돼 화면 안에서 톤이 섞이고**(툰 셰이딩은 경영 공간만, UI 에셋은 상시 노출 화면만) 반복 플레이를 지탱할 선택지가 얇다. 이번에는 (1) 절반만 끝난 룩 · UI를 마무리하고, (2) 빌드 4에서 이월된 구조 개편(자원 · 영토)을 처리하고 — **영토는 개편 대신 제거하는 선택지도 함께 검토한다**, (3) **타워 · 스킬 특수효과 종류를 늘려 판마다 다른 선택이 나오게 하고**, (4) **경영 공간의 주민 ↔ 건물 상호작용**을 붙이고, (5) 랜덤화와 밸런스의 남은 구멍을 메운다.

> **튜토리얼은 이번 범위에서 제외한다 — 베타에서 진행한다.** 안내 층은 UI · 자원 이름 · 밸런스가 확정된 뒤에 만들어야 다시 만들지 않는다. (참고: 빌드 4에서 마스터 시드 직접 입력이 들어가 **튜토리얼 전용 고정 시드**를 쓸 수 있게 됐으므로, 착수 시 별도 튜토리얼 맵은 필요 없다)
> **설정 확장**은 GDD에 명세가 없다 — 구현과 함께 GDD에 해당 절을 신설할 것.
> §1 UI 에셋 · §2 설정 확장 · §3 자원 개편 · §4 영토 개편은 빌드 3에서 계획했다가 **두 번째로 이월**된 항목이다. 이번에도 밀리면 범위를 줄여서라도 착수 여부를 먼저 정할 것.

### 1. UI 에셋 적용

빌드 4에서 **상시 노출 화면까지 적용이 끝났다.** 남은 것은 **클릭해서 여는 패널 전부**와 아이콘 · 폰트다. 지금은 한 화면 안에서 새 UI(상시)와 기본 UI(패널)가 섞여 보이므로, 이번 빌드에서 마무리해야 톤이 정리된다. 에셋과 톤 기준은 빌드 4에서 확정됐다.

- **에셋** — 빌드 4에서 쓴 UI 킷을 그대로 확장 적용. 부족한 컴포넌트만 추가 조달
- **남은 적용 대상**
  - 공통: 패널 배경 · 버튼 · 슬라이더 · 토글 · 스크롤바
  - 경영: 건물 정보 · 업그레이드 패널, 본진 패널, 마법 연구소, 연금술사 상점
  - 전투: 타워 정보 패널, 합성 패널, **합성 족보 패널**
  - 기타: 타이틀(**이어하기 · 시드 입력 포함**), 설정, 보상 선택, 게임 오버 / 클리어, 미니맵 프레임
- **아이콘** — 자원, **타워 17종**, 건물, 스킬, 상태이상(스턴 · 슬로우 · 화상 · 독) (자원 아이콘은 §3 확정 후, 신규 타워 아이콘은 §6과 세트)
- **폰트** — 게임 톤에 맞게 교체. **ko / en / ja 글리프를 모두 포함**하는지 확인
- **레이아웃 정리** — 기준 해상도 · Canvas Scaler Match 값 통일, 렌더 순서 재점검

### 2. 설정 확장

현재 설정 패널에는 **언어 변경 · 타이틀로 · 게임 종료**만 있다.

- **오디오** — 마스터 / BGM / SFX 볼륨 (오디오 도입과 세트, §7)
- **게임플레이 편의** — 카메라 이동 · 줌 감도, 데미지 표시 · 사거리 상시 표시 토글(여유 시)
- **설정 값 영속화** — 현재 언어만 `PlayerPrefs`에 저장된다. 나머지도 같은 방식으로 저장하고 시작 시 일괄 적용
- 타이틀 씬과 인게임 양쪽에서 동일하게 동작해야 한다

### 3. 자원 개편

`ResourceKind` 8종(나무 · 철 · 식량 · 마나 + 금 · 루비 · 사파이어 · 다이아)인데 **어떤 자원이 어디에 쓰이는지가 불분명하다.** 특수 자원 4종은 수급 경로(영토)만 있고 소비처가 뚜렷하지 않다. 빌드 3에서 이월된 항목이며, **빌드 4에서 타워가 17종으로 늘고 합성 전용이 10종(3단계 합성 포함)이 되면서 소비처 설계 여지가 크게 커졌다.**

- **소비처 매트릭스 확정** — 자원 × 사용처(타워 배치 · 타워 합성 · 건물 건설 · 건물 업그레이드 · 본진 업그레이드 · 스킬 업그레이드 · 연금술사 교환) 표를 만들어 GDD에 싣는다. **소비처가 없는 자원은 만들지 않는다.**
- **역할 분리** — 기본 자원(상시 수급, 저렴한 반복 소비) / 마나석(웨이브 보상, 성장 통화) / 특수 자원(영토 보상, 고급 해금 전용)이 겹치지 않게
- **특수 자원 4종의 용도 부여** — **합성 전용 상위 타워의 추가 비용**이 유력한 자리다(현재 합성 전용 10종은 전부 `Cost:[]`이고 레시피의 `ExtraCost`도 전부 비어 있다). 3단계 합성(단일 인페르노)이 생겨 **깊이에 따라 비용을 차등하기 좋은 구조**가 됐다
- **이름 · 아이콘 개편** — 에셋 톤에 맞게. `ResourceKind` enum 값 순서는 직렬화 인덱스 때문에 **변경 금지** — 표시 이름은 `NameKey`로만 바꾸고 3개 언어 갱신
- **세이브 스키마 영향 확인** — 자원은 절대값으로 저장된다. 종류를 줄이면 구 세이브 마이그레이션이 필요하다

- **§4 영토 존폐가 선행 조건이다** — 영토를 제거하면 특수 자원 4종의 수급 경로가 사라져 자원이 4종(기본 3 + 마나석)으로 줄고, 아래 두 질문이 자동으로 답해진다. **영토를 먼저 정하지 않으면 이 절의 작업이 헛일이 될 수 있다**
- 자원 종류를 8종 그대로 갈 것인가, 줄일 것인가
- 특수 자원 4종을 각각 다르게 쓸 것인가, 하나의 "고급 자원"으로 묶을 것인가
- 새 이름 목록(ko / en / ja)

### 4. 영토 — 개편 또는 제거

확보하면 고유 자원이 매일 자동 수급되는 것 외에 할 수 있는 일이 없다. 빌드 3에서 이월.

**먼저 정할 것 — 개편할 것인가, 걷어낼 것인가.**

두 번째 이월이라는 사실 자체가 신호다. 영토는 지금 **"매일 클릭 한 번 = 자원 라인 하나"** 로만 동작하고, 그 클릭이 선택으로 느껴지지 않는다(인접이면 그냥 확보 가능, 강제 1회). 개편 후보를 다 넣으면 사실상 새 시스템 하나를 만드는 일이라, **아예 제거하는 선택지를 같은 무게로 검토한다.**

- **제거하면 얻는 것** — 매일 반복되는 무의미한 클릭이 사라지고, 자원 종류가 8종에서 4종(기본 3 + 마나석)으로 줄어 §3 자원 개편의 난제 절반이 자연히 풀린다. 시드 연결 대상 · 세이브 스키마 · 노드 UI · 그래프 생성 규칙이 통째로 유지 대상에서 빠진다. **남는 인력을 타워 · 보상 밸런스와 UI 마무리에 돌릴 수 있다**
- **제거하면 잃는 것 / 대체가 필요한 것**
  - **특수 자원 4종(금 · 루비 · 사파이어 · 다이아)의 유일한 수급 경로가 사라진다.** 자원을 함께 없앨지, 다른 경로(웨이브 보상 · 연금술사 교환)로 옮길지 정해야 한다
  - **본진 주민 수 증가의 후반 회차가 특수 자원을 요구한다**(§GDD 5.1) — 비용 테이블을 기본 자원으로 다시 짜야 한다
  - 경영 공간의 **성장 축이 건물 업그레이드 하나만 남는다.** 낮에 할 일이 줄어드는 만큼 다른 선택지(건물 신축 · 주민 조작)가 그 자리를 메울 수 있는지 확인
  - GDD의 **핵심 컨셉 중 하나**(§3.1 "두 공간의 독립적 이중 확장")가 무너진다 — 전투 공간만 확장되면 컨셉을 다시 써야 한다. **이게 제거의 가장 큰 비용이다**
  - 레퍼런스로 든 Slay the Spire식 노드 경로 선택 구조(§2)도 함께 사라진다

**개편으로 간다면 — 손볼 후보**
  - 영토마다 성격 부여 — 자원 종류 · 양뿐 아니라 특수 효과(생산 보너스 · 방어 · 해금 등)
  - 확보 이후의 상호작용 — 영토 자체를 개발/업그레이드할 수 있는지
  - 확보 비용과 조건 — 현재는 인접이면 확보 가능. 자원 소모 · 일차 제한 · 웨이브 클리어 요구 등
  - 시각적 표현 — 확보/미확보/확보 가능 상태 구분
- **세이브 영향** — 영토는 노드 ID로 저장된다. 생성 규칙을 바꾸면 같은 시드에서도 ID 대응이 달라질 수 있으니 마이그레이션 여부 확인

**결정 필요**
- **영토 시스템을 유지할 것인가, 최소 범위로 고정할 것인가, 제거할 것인가** — §3 자원 개편의 선행 조건이다. 특수 자원 4종의 존폐가 여기서 갈리므로 **자원 소비처 매트릭스를 짜기 전에 먼저 답해야 한다**
- 제거로 간다면 GDD §3.1(이중 확장 구조) · §2(노드 경로 레퍼런스)를 어떻게 다시 쓸 것인가

### 6. 콘텐츠 확장 — 타워 · 스킬 특수효과

한 판의 구조는 완성됐지만 **판마다 다른 선택이 나오게 하는 재료가 한쪽으로 치우쳐 있다.** 타워는 빌드 4에서 17종까지 늘었지만 **보상은 여전히 4종뿐**이라 서너 웨이브면 다 보인다. 이번에는 보상 축을 따라잡게 하고, 타워는 개수보다 **역할 정리와 밸런스**에 무게를 둔다.

**보상 스킬 특수효과 확장** (현재 4종 — 화상 · 폭탄 · 추가시전 · 버프화상)

- 3택1 후보 풀이 4종이면 **레벨 상한(3)까지 올리는 데 12회 선택이면 전부 만렙**이라 후반 보상이 비어 버린다. GDD §5.6의 "상한 3"과 함께 **적정 종류 수를 역산**할 것 — 웨이브 수(§5 확정)와 세트로 판단한다
- 추가 후보 방향 — 감전 축(연쇄 · 감전 지속 · 처치 시 폭발), 시전 축(쿨다운 감소 · 시전 범위 확대), 버프 축(지속시간 · 타워 사거리 버프)
- **추가 비용은 구조상 매우 낮다** — `SkillEffect` 파생 1개 + `GameScene`의 `SkillEffectManager`에 컴포넌트 부착 + 보상 SO 1개. 스킬 본체 · 매니저는 무수정이다(`PlayerSkill.md` §4 절차)
- 주의 3가지
  - `WaveRewardType`에 값을 추가할 때는 **반드시 맨 뒤에** — enum이 int로 직렬화돼 순서를 바꾸면 기존 보상 에셋이 다른 타입이 된다
  - `GetStatSummary()` 구현 필수(추상) + 라벨은 `SkillStatsFormatter` · `NorthLand_Skills` 테이블에 — 수치 없는 카드가 조용히 나가는 것을 막는 강제 장치다
  - **세이브 마이그레이션** — 보상 레벨은 타입별 절대값으로 저장된다. 종류를 늘리는 것은 안전하지만 지우거나 순서를 바꾸면 구 세이브가 깨진다
- **메테오처럼 "이동 + 지연 데미지"가 붙는 연출은 이 축에 넣는다** — 마법 연구소 축(즉발 이펙트 교체)이 아니다. `BombEffect`+`SkillBomb`이 이미 그 패턴을 확립해 뒀다

**타워 — 개수보다 정리** (현재 17종 — 직접배치 7 / 합성 전용 10)

빌드 4의 **부품 조립화**(액션 리스트 · `HitEffect` · 비행 축 SO 이관 · 램프 부품 · 합성 효과 계승) 덕분에 **기존 부품 조합만으로 신규 타워를 만들 수 있게 됐고**, 그 구조로 한 빌드에 9종이 들어왔다. 만드는 비용이 낮아진 만큼 **이번에는 늘리는 것보다 정리가 급하다.**

- **역할 중복 정리 우선** (§5와 함께) — 17종 중 서로를 대체하는 축이 없는지 본다. 직접배치 7종은 초반 선택지라 특히 겹치면 안 된다
- **성장형 3종의 밸런스 실측** — 램프업(공속 +8%×10) · 사냥꾼(공격력 +15%×8) · 단일 인페르노(스택당 +150%×8)는 **표기 스탯과 실효치가 크게 갈린다.** 특히 단일 인페르노는 상한에서 십수 배가 되므로, 3단계 합성이라는 도달 난도로 충분히 균형이 잡히는지 확인할 것
- **합성 깊이 표현** — 3단계 합성(단일 인페르노)이 생겼는데 족보 패널이 아직 테스트용이다. 정식 UI 없이 "궁수 6기 → 단일 인페르노" 경로를 플레이어가 알아낼 수 있는지 (§1 UI 작업과 연결)
- 더 늘린다면 **지금 없는 역할부터** — 광역 디버프, 대공 전용 등. 직접배치를 늘릴지 합성 전용을 늘릴지는 로스터 축소 사인오프(WL-156) 결론이 선행 조건이다
- `lightning_tower` 배선 또는 폐기 결정을 이 작업과 묶는다(§5) — 지금은 SO만 있고 획득 불가다
- 신규 타워마다 **아이콘 · 이름 · 설명(ko/en/ja)** 이 따라온다(§1 아이콘 작업과 세트). 이번 9종분이 이미 밀려 있다

**결정 필요**
- 특수효과를 몇 종까지 늘릴 것인가 — 웨이브 수(§5)와 보상 상한(3)에서 역산
- 타워를 더 늘릴 것인가, 17종에서 멈추고 밸런스에 집중할 것인가
- 성장형 축을 더 밀 것인가 — 지금 3종이 한 번에 들어와 축의 비중이 커졌다
- 특수효과 추가가 3택1 후보 풀 희석으로 이어지지 않는지(원하는 빌드로 못 가는 문제)

### 8. 주민 ↔ 건물 상호작용

빌드 4에서 주민이 살기 시작했지만 **화면의 주민과 경영 시스템이 아직 이어져 있지 않다.** 패널에서 `+`를 눌러도 숫자만 줄고, 화면의 주민은 그대로 돌아다닌다. 배정이 "무슨 일이 일어났는지 보이지 않는" 조작으로 남아 있다.

**직접 조작 — 선택 후 건물 클릭**

- 드래그 사각형 또는 클릭으로 **주민을 선택**(빌드 4에서 선택·아웃라인까지 구현됨) → **생산 건물을 클릭**하면 선택한 주민이 그 건물로 배정된다
- 배정된 주민은 **NavMesh로 건물 입구까지 걸어가 안으로 들어간다.** 즉시 사라지지 않는다 — 밤에 건물로 귀가하는 기존 동작과 같은 경로를 재사용한다
- 여러 명을 선택했으면 건물 정원만큼만 들어가고 나머지는 선택이 유지된다
- 배정 불가(정원 초과 · 밤 · 대상이 생산 건물이 아님)일 때 **아무 일도 안 일어나는 대신 이유가 보여야 한다** — 커서 · 아웃라인 색 · 짧은 토스트 중 택1
- 해제 조작도 함께 정한다 — 건물을 클릭해 빼내는지, 패널 `-` 만 쓰는지

**패널 배정에도 연출을 붙인다**

- 패널에서 `+`를 눌러도 **유휴 주민 중 하나가 실제로 그 건물로 걸어 들어간다.** `-`를 누르면 건물에서 나온다
- 지금은 숫자만 바뀌어 배정이 체감되지 않는다. 두 경로(직접 조작 · 패널)가 **같은 결과**로 수렴해야 한다
- 걸어가는 도중 낮이 끝나거나 배정이 취소되면 어떻게 되는지 정할 것 — 이동 중 상태를 시스템이 알아야 한다

**선행 과제 (구조)**

- `AssignVillager`가 `void`라 **성공 여부를 알 수 없다** — 직접 조작은 실패 피드백이 필수라 반환 계약부터 고쳐야 한다
- 주민 선택 상한이 "표시만 막는" 구현이라 정보 패널·배정이 붙으면 어긋난다 (WL-158)
- 배정된 주민의 **저장·복원** — 현재 세이브는 배정 수만 절대값으로 갖는다. 이동 중 상태를 저장할지, 낮 시작 시점(자동 저장 시점)엔 이동이 끝나 있다고 볼지 결정

**나머지 주민 축**

- **밀도 의존 수치 5종 재실측** — 정본 씬 기준으로. 춤이 사문화됐는지 먼저 확인 (WL-153)
- 밤 일괄 수거 시 대화 세션이 해산 쿨다운을 못 밟는 문제 (WL-159)
- 후속 콘텐츠 후보 — 직업 · 공연 · 구경(R13/R14)

**결정 필요**
- 조작 모델 — 선택 후 건물 클릭 / 들어서 드롭(드래그 앤 드롭) 중 어느 쪽인가. 타워 배치가 이미 "버튼 → 고스트 → 클릭" 이라 **일관성 기준으로 판단할 것**
- 배정 해제를 화면 조작으로 열 것인가, 패널 `-` 만 둘 것인가

### 9. 룩 마무리 — 전투 공간 · 연출

빌드 4에서 툰 셰이딩이 **경영 공간에만** 적용됐다. 같은 화면에서 낮/밤을 오가는 게임이라 두 공간의 그림이 갈리면 바로 보인다.

- **전투 공간 머티리얼 변환** — 경영 공간 115개를 변환한 규모를 감안해 일정을 잡을 것. 타일 · 타워 · 몬스터 · 투사체가 대상
- **픽셀 필터 확인** — 렌더러 피처 설정을 **PC · Mobile 파이프라인 에셋 양쪽**에 적용했는지 점검(현재 `PixelationSettings_PC`만 확인됨, CLAUDE.md 규약)
- **타워 배치 · 합성 연출의 아트 방향 확정** — 현재는 임시 버전이다. 이대로 확정할지, 룩에 맞춰 다시 만들지 결정
- 물에 닿지 않았는데 화면상 닿아 보이면 거품이 생기는 문제 (빌드 3에서 이월)
- 최대 축소 시 주민이 점으로 보임 — 오쏘 카메라라 거리 보정이 무효

## 사전에 확정해야 할 것

- **이번 빌드 범위 우선순위** — §1 UI 킷 · §3 자원 개편이 두 번째 이월 항목이다. 여기에 §9(전투 공간 툰 셰이딩)가 더해지는데, 빌드 4에서 절반만 적용된 축이라 **미루면 톤이 섞인 화면이 한 빌드 더 나간다**. §6 콘텐츠 확장 · §8 주민 상호작용은 이번에 새로 들어온 축이므로 이월 항목과의 우선순위를 먼저 정할 것
- **튜토리얼을 베타로 미룬 결정 재확인** — 안내 층은 UI · 자원 이름 · 밸런스 확정 이후가 맞는지
- 타워 배치 · 합성 연출을 임시 버전으로 확정할지, 룩에 맞춰 다시 만들지 (§9)
- **영토 시스템의 존폐 (§4) — 이번 빌드에서 가장 먼저 답해야 할 질문이다.** 유지 / 최소 범위 고정 / 제거 셋 중 하나. 두 번째 이월이고, 결론이 §3 자원 개편(특수 자원 4종의 존폐) · 세이브 마이그레이션 · GDD §3.1 이중 확장 컨셉까지 연쇄로 정한다
- 자원 소비처 매트릭스와 새 이름 목록 — §3이 §1(아이콘) · 세이브 스키마의 선행 조건이고, 그 §3은 다시 §4 영토 결론에 달려 있다
- **특수효과 · 타워를 몇 종까지 늘릴 것인가** (§6) — 웨이브 수와 보상 상한(3)에서 역산해야 하므로 웨이브 수 확정이 선행
- **주민 배정 조작 모델** (§8) — 선택 후 건물 클릭 / 들어서 드롭 중 택1. 타워 배치 조작과의 일관성 기준으로 판단
- 영토를 유지한다면 개편 목표와 이번 빌드 범위, 노드 ID 마이그레이션 필요 여부
- 랜덤화 잔여 범위(버프 타일 · 웨이브 · 보상)와 난이도 검증 기준
- 직접배치 로스터 축소(11 → 7종) 사인오프 — 반려 시 개틀링 · 스나이퍼 패널 복귀
- 합성 족보와 합성 추가 비용(특수 자원 사용 여부)
- 전체 웨이브 수 확정 — 맵 공개 페이스와 승리 조건의 단일 출처
- UI 킷 · 폰트 · 오디오 에셋 조달 및 라이선스
- 기준 해상도 및 지원 해상도 목록
- 세이브 포맷 변경 시 마이그레이션 정책(구 세이브 무시 vs 변환) — v1이 이미 배포됐다
